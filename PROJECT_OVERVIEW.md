# AI Council — Project Overview

A local-first, multi-LLM meeting platform where AI personas debate, collaborate, and advise — led by the user as facilitator.

---

## Core Concept

The user builds a library of AI **personas**, each backed by a specific LLM provider and model. They set up **meetings** by selecting personas, defining speaking order, and configuring rounds. The meeting runs like a structured real-world discussion: personas speak in turn, the user can intervene at any point, and any participant can address any other directly via @mention.

---

## Feature Set

### Personas

- Each persona has: **name**, **emoji**, **avatar color**, **role title**, **system prompt**, **provider**, **model**, **max tokens**
- Stored in a **personal library** and reused across meetings
- Full CRUD: create, edit, delete

**One-click Prompt Generator** — instead of writing a system prompt manually, the user fills in:
- Expert field (e.g. "Cybersecurity", "Product Strategy")
- Role archetype (e.g. "Devil's Advocate", "Skeptic", "Strategist")
- Creativity level: Low / Medium / High
- Knowledge depth: Generalist / Expert / Domain Master
- Communication style (freeform, e.g. "Concise and blunt")
- Optional extra instructions

One click generates a full system prompt via Claude and populates the field. User can edit before saving.

---

### Meetings

**3-step creation wizard:**
1. Title + description
2. Select personas from library, set speaking order
3. Configure rounds, synthesis mode, Note Taker, optional agenda/notes

**Meeting brief on start:**
When a meeting begins, every persona receives a context injection containing:
- Meeting title + description
- Full participant list (name + role for each persona)
- Their own position in the speaking order
- Agenda notes (if provided)

This ensures all personas "know the room" before speaking.

**Structured rounds:**
- Personas speak in defined order, one at a time
- After each persona's response, the user sees a **Confirm & Continue** button
- User can type a facilitator comment (injected as context for the next speaker)
- All personas completing one turn = 1 round; repeats for N configured rounds
- **Auto-advance mode**: optionally skip the confirm step and advance automatically

**Free @mention (anytime):**
- User types `@PersonaName message` to directly address a specific persona at any point
- That persona responds immediately, outside the round order
- Personas can @mention each other in their own responses
- If a persona is currently streaming when a mention arrives, it is **queued** and fires after the stream ends — no interruption

**Conduct rules (built into every persona's context):**
1. Keep responses focused and under the configured max tokens
2. Directly address the question or statement at hand
3. Engage with other participants — acknowledge, challenge, build upon their points
4. Never break character — stay in role for the entire meeting
5. If the topic is entirely outside your defined expertise, say so briefly (1–2 sentences) and defer

---

### Synthesis Modes

Configurable per meeting; controls what happens after all rounds complete:

| Mode | Behaviour |
|------|-----------|
| **Off** | Meeting ends after the last round |
| **Individual verdicts** | Each persona delivers a closing synthesis statement in order |
| **Shared verdict** | Individual closings + a unified **Council Verdict** generated by one model across all synthesis statements |

The Council Verdict uses the first persona's provider/model as a neutral summariser.

---

### Note Taker

Optional post-meeting feature. After the meeting completes (and synthesis, if enabled), the Note Taker fires automatically:

- Builds a full transcript of the meeting
- Sends it to a configured provider/model (independent of the personas)
- Streams a structured summary including:
  - Per-persona position summary
  - Points of agreement and disagreement
  - Overall arc of the discussion
  - Action items (if applicable)

Rendered in the meeting room with a distinct sky-blue card style.

---

### Per-turn Retry

If any LLM call fails mid-meeting, the error message renders with a **Retry** button. Clicking it:
1. Deletes the error message from the store
2. Replays the exact same request (same round, type, parameters)

For @mention replies, the original message text is stored on the message (`overrideMessage`) so replay is faithful.

---

### Pre-flight Validation

Before a meeting starts, the platform checks that all API keys / Ollama base URLs are configured for the providers used by the selected personas. Missing keys surface a clear error message naming the provider, linking to Settings — no silent mid-meeting failures.

---

### Meeting History

- All meetings saved locally with full message history
- Listed on the history page with title, date, persona count, round count, status badge
- Status: `draft` → `in_progress` → `completed`

---

### Export

Each completed meeting is exportable as:

- **Markdown** — human-readable transcript with headers, speaker labels, round/synthesis labels, timestamps; Note Taker summary and Council Verdict in dedicated sections
- **JSON** — full structured data (meeting config, personas, all messages)

---

### Settings

- Enter and save API keys:
  - Anthropic (Claude)
  - OpenAI
  - Google (Gemini)
  - Ollama base URL (default: `http://localhost:11434`)
- Keys stored in localStorage only — never persisted server-side

## Meeting Flow

```
Start meeting
  → pre-flight API key check
  → broadcast brief to all personas (system messages)
  → Round 1 begins

  For each round:
    For each persona (in order):
      → stream persona response
      → [autoAdvance off] user sees Confirm button, optionally adds comment
      → [autoAdvance on]  advances immediately

  After all rounds:
    [synthesisMode = individual | shared]
      → each persona streams a closing synthesis statement
    [synthesisMode = shared]
      → Council Verdict streamed (unified synthesis across all closing statements)

  [noteTakerEnabled]
    → Note Taker streams a full meeting summary

Meeting status → completed

@mention (anytime):
  → if a stream is active: queued, fires on stream end
  → otherwise: fires immediately as a direct_reply
  → errors show Retry button; retry deletes error and replays the request
```

## Design Principles

- **Local-first** — no accounts, no cloud sync, all data in browser localStorage
- **Facilitator-led** — user controls pacing; no persona speaks without confirmation (unless auto-advance is on)
- **Identity-aware** — every message is attributed: persona name, LLM badge, round, timestamp
- **Provider-agnostic** — any persona can use any LLM; mix providers freely in a single meeting
- **Resilient** — per-turn retry on stream failure; pre-flight key validation; @mention queuing
- **Exportable** — meetings are data artifacts; always exportable as Markdown or JSON

---

## Known Limitations / Future Work

- **Context window pruning** (`IMPROVEMENTS.md #1`): In long meetings the full history is sent on every API call. A smart pruning strategy (keep current round in full, one representative turn per persona per earlier round, never drop facilitator messages) would reduce costs and prevent token-limit failures.
